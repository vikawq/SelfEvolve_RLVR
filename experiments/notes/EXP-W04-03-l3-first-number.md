## 结果（负结果 + 训练崩溃）

| 指标 | 值 |
|---|---|
| 训练侧宽松奖励（最后 20 步） | **0.090** |
| 训练侧严格准确率（最后 20 步） | **0.090** |
| reward gap（最后 20 步） | **0.000**（onset 不适用） |
| 严格准确率轨迹（每 5 步均值） | 0.30 → 0.13 → 0.08 → 0.07 → 0.06 → 0.03 → 0.04 → … → **0.09** |
| 首数字位置（均值） | 19.3 字符（很早） |
| 典型输出 | `#### 4`、`#### 5`、`#### ###.2`（6–10 字符，无推理） |
| **GSM8K test 前 500（严格）** | 基座 0.478 → step100 **0.064** → step200 **0.086** |
| **MATH-500（严格）** | 基座 0.332 → step100 **0.072** → step200 **0.074** |
| 训练步时 / 峰值显存 | 约 45 s / 10 GiB |

为什么 gap 最后是 0：模型退化到只写 `#### <猜测>`，此时"第一个数字"和"最终答案"是同一个数，
宽松与严格判定自然一致（都约 0.09）。gap 为 0 不代表正常，而是"两个指标一起归零"。

## 结论：这个漏洞不能被利用，但能摧毁模型

1. **不可利用**：第一个数字通常是**题面**里的数字（"Natalia sold 48 clips..." 的第一个数字是 48），
   等于金标的概率极低。前 38 步宽松奖励最高只有 0.05，而严格准确率同期是 0.04–0.30；
   gap 始终**为负或零**，模型没有从中骗到任何额外奖励。
2. **反而崩溃**：奖励几乎全 0 → GRPO 的组内优势几乎全 0；模型退化成"只输出一个猜测"的
   6–10 字符响应，GSM8K 从 0.478 掉到 **0.086**、MATH-500 从 0.332 掉到 **0.074**。
   这是"奖励过稀疏 + 目标错位"导致的能力垮塌，不是 hacking。
3. **与 L1/L2 的区别**：L1 是代理奖励膨胀（能力不变），L2 是代理奖励上升 + 真实能力下降，
   L3 是**代理奖励本身都拿不到**，只留下破坏。任务包已经预见到这种可能
   （"没能复现的类型要有分析：是步数不够、模型太小，还是这个漏洞根本无法被利用？"），
   这里的答案是：**漏洞本身不可被利用，且奖励设计会把模型训崩**。
4. 对 W5 的意义：防御实验不能只测"宽松判分器"，还要测"错误/稀疏的奖励"——
   D1（严格 verifier）不仅是防 hack，也是防这种 collapse 的基线。
